# Audio Deepfake Detection Branch

## Overview

This branch implements a high-performance audio spoofing detection system capable of identifying AI-generated or voice-cloned speech. The system leverages OpenAI's Whisper transformer as a deep semantic feature extractor, paired with an XGBoost classifier to discriminate between genuine (bonafide) human speech and synthetic/spoofed audio.

The pipeline was trained and evaluated on the industry-standard ASVspoof 2019 Logical Access (LA) benchmark dataset, achieving near-perfect discrimination across a wide range of TTS (Text-To-Speech) and Voice Conversion attacks. The main objective is to detect malicious modifications to the acoustic signal without the need to fine-tune massive audio models, maximizing both accuracy and computational efficiency.

### About ASVspoof 2019 LA

The ASVspoof 2019 Logical Access scenario targets text-to-speech (TTS) and voice conversion (VC) attacks. Spoofed utterances are generated by 17 distinct attack algorithms (A01-A17), covering a diverse range of neural TTS and voice conversion architectures. Bonafide samples are real human recordings from the VCTK corpus.

**Class Imbalance Note:** The dataset has a significant class imbalance (~1:9 bonafide-to-spoof ratio). This was explicitly addressed during the training of the XGBoost classifier by applying the `scale_pos_weight` parameter to penalize misclassification of the minority class proportionally.

## Model Architecture & Algorithms

### Pipeline: Whisper Encoder to XGBoost Classifier

```text
Audio File (.flac / .wav / .mp3)
        |
  librosa.load() @ 16kHz
        |
  WhisperProcessor (feature extraction)
        |
  Whisper-Base Encoder (frozen)
        |
  last_hidden_state.mean(dim=1)   ->   512-dim embedding
        |
  XGBoost Classifier
        |
  [Bonafide / Spoof] + Confidence Score
```

### 1. Feature Extractor: Whisper-Base Encoder

| Parameter | Value |
|---|---|
| **Model** | `openai/whisper-base` |
| **Source** | HuggingFace Transformers |
| **Parameters** | ~74M |
| **Embedding Dim** | 512 |
| **Pooling** | Mean pooling over temporal sequence |
| **Inference Mode** | Frozen (no gradient updates) |

**Why Whisper?** Whisper was pre-trained on 680,000 hours of multilingual speech for automatic speech recognition. Its encoder learns rich acoustic representations that capture both phonetic content and acoustic characteristics. Critically, TTS and voice conversion systems leave subtle artifacts in the frequency and temporal domain that Whisper's representations encode, making it a powerful zero-shot feature extractor for spoofing detection.

**Extraction Process:**
1. Audio is loaded with `librosa` at a 16kHz sampling rate.
2. The `WhisperProcessor` converts the waveform into 80-channel Log-Mel spectrogram features.
3. The frozen Whisper encoder processes the features into a sequence of hidden states `(T x 512)`.
4. Mean pooling across the time dimension yields a single global 512-dimensional embedding representing the entire audio clip.

### 2. Classifier: XGBoost

| Parameter | Value |
|---|---|
| **Algorithm** | XGBoost (Gradient Boosted Decision Trees) |
| **`n_estimators`** | 1000 |
| **`learning_rate`** | 0.05 |
| **`max_depth`** | 6 |
| **`eval_metric`** | AUC |
| **`early_stopping_rounds`** | 50 |
| **`scale_pos_weight`** | `count(bonafide) / count(spoof)` approx 0.113 |
| **`random_state`** | 42 |

**Why XGBoost?** Given the high-quality 512-dim Whisper features, a gradient boosted tree classifier achieves near-perfect separation without the training instability of end-to-end neural networks. XGBoost is also highly interpretable through feature importance scores and handles class imbalance natively via the `scale_pos_weight` hyperparameter.

## Training Methodology

### Phase 1: Feature Extraction (Offline)

All 25,380 training audio files were processed through the frozen Whisper encoder in a single pass. This offline extraction approach:
- Eliminates redundant computation during XGBoost training.
- Enables reproducibility across multiple classifier training runs.
- Reduces memory overhead by storing embeddings as `.npy` files.

**Processing Speed:** ~22.9 samples/second on Tesla T4 GPU.
**Total Extraction Time:** ~18.5 minutes for the training set (25,380 files).

### Phase 2: XGBoost Training

```text
Training Split: 70% Train | 30% Internal Test (Stratified)
Dataset: X=(25380, 512), y=(25380,)
```

Training was monitored with AUC on both the training and internal test sets, implementing early stopping to prevent overfitting. The model converged smoothly without severe performance decay on validation boundaries.

| Iteration | Train AUC | Test AUC |
|---|---|---|
| 0 | 0.9504 | 0.9221 |
| 50 | 0.9989 | 0.9903 |
| 100 | 0.9999 | 0.9951 |
| 200 | 1.0000 | 0.9976 |

### Memory Management

For the massive 71,237-sample evaluation set, CUDA memory was manually flushed every 500 iterations to prevent GPU OOM (Out Of Memory) errors, highlighting careful system resource management:

## Key Strengths & Design Decisions

1. **Transfer Learning from ASR to Anti-Spoofing:** Whisper's encoder, trained for speech recognition, learns universally useful acoustic features. TTS artifacts that disrupt natural prosody and spectral continuity are well-captured in this representation space, eliminating the need to train complex models from scratch.

2. **No End-to-End Fine-tuning Required:** The frozen Whisper encoder achieves remarkable performance without gradient updates. This reduces training time from hours to minutes and successfully avoids catastrophic forgetting.

3. **Efficient Offline Feature Cache:** By pre-computing all embeddings, the XGBoost training loop runs in seconds rather than hours, enabling rapid hyperparameter experimentation and model optimization.

4. **Native Class Imbalance Handling:** XGBoost's `scale_pos_weight` parameter directly compensates for the 1:9 bonafide-to-spoof ratio without requiring memory-intensive oversampling or information-losing undersampling techniques.

5. **Resource Scalability:** Dynamic garbage collection and `torch.cuda.empty_cache()` calls during extraction ensure stable batch processing on consumer-grade hardware.
